# Перенос бота на второй компьютер и публикация кода

Документ для того, кто будет ставить бота на рабочий ПК. Ничего программировать не нужно —
только выполнить шаги по порядку.

---

## Часть 1. Что понадобится

- второй ПК: Windows 10 или 11, интернет, права администратора (для установки Python);
- файлы бота (папка `tools`) или доступ к репозиторию GitHub;
- токен бота (`tools/.tg_token` на текущем ПК);
- ключ DeepSeek (переменная `DEEPSEEK_API_KEY` на текущем ПК);
- список `chat_id` сотрудников, которым разрешено пользоваться ботом.

Время на всё: 20–30 минут.

---

## Часть 2. Установить Python

1. Открыть <https://www.python.org/downloads/> и скачать **Python 3.12** (Windows installer, 64-bit).
2. Запустить установщик. На первом экране **обязательно** поставить галочку
   **«Add python.exe to PATH»**, затем «Install Now».
3. Проверить: `Win+R` → `cmd` → Enter, в чёрном окне набрать:

   ```
   py --version
   ```

   Должно ответить `Python 3.12.x`. Если пишет «не является внутренней или внешней командой» —
   Python установился без галочки, переустановить.

Больше для бота **ничего устанавливать не нужно**. Пакеты требуются только для работы
с Excel (`openpyxl`), это отдельный режим, боту он не нужен.

---

## Часть 3. Скопировать файлы

Создать папку `C:\PalladiumAutoBot` и положить туда содержимое `tools`:

```
tg_bot.py
scan_cars.py
car_registry.py
run_bot.cmd
scan_cars.cmd
README.md
```

Не копировать: `logs`, `__pycache__`, `.tg_bot.pid` — это мусор и рабочие журналы.

Если делаем через GitHub (Часть 10), папку можно получить командой `git clone` — файлы приедут
сами, а секреты добавим вручную.

> Папку лучше держать **вне OneDrive**: синхронизация иногда блокирует файлы во время работы бота.

---

## Часть 4. Положить секреты

Секреты в репозиторий не попадают, на новом ПК их нужно создать заново.

**Токен Telegram** — файл `C:\PalladiumAutoBot\.tg_token`, внутри одна строка с токеном:

```
8123456789:AAH4kLmNoPqRsTuVwXyZ1234567890abcde
```

Создать можно блокнотом: «Файл → Сохранить как», имя `.tg_token`, тип «Все файлы»,
кодировка UTF-8.

**Ключ DeepSeek** — файл `C:\PalladiumAutoBot\.deepseek_key` с ключом, так же.

Вместо файлов можно задать системные переменные (PowerShell):

```powershell
[Environment]::SetEnvironmentVariable("TELEGRAM_BOT_TOKEN","<токен>","User")
[Environment]::SetEnvironmentVariable("DEEPSEEK_API_KEY","<ключ>","User")
```

После этого перезайти в систему или перезапустить окно консоли.

---

## Часть 5. Настроить доступ

1. Взять `tg_config.example.json`, переименовать в `tg_config.json`.
2. Вписать `chat_id` сотрудников:

```json
{"allowed_chat_ids": [5085693770, 1234567890], "max_per_minute": 3}
```

`chat_id` сотрудник узнаёт сам: пишет боту `/start`, тот отвечает числом
(если список пуст — бот отвечает «Бот ещё не настроен. Ваш chat_id: …»).

После любой правки этого файла бота нужно перезапустить.

---

## Часть 6. Первый запуск вручную

1. Двойной клик по `run_bot.cmd`.
2. В окне должно появиться:

   ```
   Старт: @PalladiumAutoBot (id 9147971503), допущено чатов: 1
   ```

3. Отправить боту фото техпаспорта — должен прийти ответ с кнопками.
4. Остановить: закрыть окно (или Ctrl+C).

Если что-то не так — смотреть `C:\PalladiumAutoBot\logs\tg_bot.log`.

---

## Часть 7. Автозапуск при включении

1. `Win+R` → `taskschd.msc` → Enter.
2. Справа «Создать задачу…» (именно «Создать задачу», не «простую»).
3. Вкладка **Общие**: имя `Palladium Auto Bot`, галочка «Выполнять только при входе пользователя».
4. Вкладка **Триггеры** → «Создать» → «Начало задачи: **При входе в систему**» → ОК.
5. Вкладка **Действия** → «Создать» → «Запуск программы»:
   - Программа: `C:\PalladiumAutoBot\run_bot.cmd`
   - Рабочая папка: `C:\PalladiumAutoBot`
6. Вкладка **Условия**: снять «Запускать задачу только при питании от сети» (если ноутбук).
7. ОК. Пароль не спросят, потому что задача запускается при входе пользователя.

Проверка: в списке задач найти `Palladium Auto Bot` → правый клик → «Выполнить» →
в `logs\tg_bot.log` появляется новая строка «Старт».

Важно: бот живёт, пока пользователь **в системе**. Блокировка экрана — нормально,
«Выход из системы» — нет.

## Часть 8. Чтобы компьютер не засыпал

В PowerShell **от имени администратора**:

```powershell
powercfg /change standby-timeout-ac 0
powercfg /change hibernate-timeout-ac 0
powercfg /change monitor-timeout-ac 10
```

Это отключает сон и гибернацию при питании от сети; монитор по-прежнему гаснет через 10 минут.
Если ПК — ноутбук, проверить также, что при закрытии крышки он не уходит в сон
(«Электропитание» → «Действие при закрытии крышки» → «Ничего не делать»).

3. Через минуту открыть `logs\tg_bot.log` — должна быть свежая строка «Старт».

## Часть 10. Репозиторий на GitHub

Код уже лежит в локальном репозитории (`tools/.git`), первый коммит сделан. Осталось залить.

### 10.1 Создать пустой репозиторий

1. Войти на <https://github.com> (если нет аккаунта — зарегистрировать).
2. Кнопка **New repository**.
3. Имя: `palladium-auto-bot`. Видимость: **Private**.
4. **Не ставить** галочки «Add a README», «Add .gitignore», «Choose a license» — репозиторий
   должен быть пустым.
5. **Create repository**. Скопировать адрес вида
   `https://github.com/ВАШ_ЛОГИН/palladium-auto-bot.git`.

### 10.2 Залить код с текущего компьютера

PowerShell:

```powershell
cd "C:\Users\ighiz\OneDrive\Палладиум\05_Сервис\tools"
git remote add origin https://github.com/ВАШ_ЛОГИН/palladium-auto-bot.git
git push -u origin main
```

При первом обращении откроется окно входа GitHub — войти и разрешить доступ
(Git Credential Manager запомнит).

### 10.3 Проверить, что секретов нет

На сайте репозитория в списке файлов **не должно быть** `.tg_token`, `.deepseek_key`,
`tg_config.json`, папки `logs`. Если что-то из этого попало — сразу удалить файл,
а токен и ключ перевыпустить.

Локальная проверка:

```powershell
git ls-files
```

Команда показывает, что реально хранится в репозитории.

## Часть 11. Второй компьютер: получить код из GitHub

1. Установить **Git for Windows**: <https://git-scm.com/download/win> (везде «Далее»).
2. PowerShell:

   ```powershell
   cd C:\
   git clone https://github.com/ВАШ_ЛОГИН/palladium-auto-bot.git PalladiumAutoBot
   ```

3. Войти в GitHub, если попросит.
4. Создать `.tg_token` и `.deepseek_key` (Часть 4) и `tg_config.json` (Часть 5) — их в репозитории нет.
5. Дальше по Частям 6–9.

## Часть 12. Как обновлять код

Правки делаются в одном месте, затем:

```powershell
cd "C:\Users\ighiz\OneDrive\Палладиум\05_Сервис\tools"
git add -A
git commit -m "что изменил"
git push
```

На втором ПК:

```powershell
cd C:\PalladiumAutoBot
git pull
```

После обновления перезапустить задачу: Планировщик → `Palladium Auto Bot` →
«Завершить», затем «Выполнить».

## Часть 13. Если что-то не работает

| Симптом | Причина | Что делать |
|---|---|---|
| `py` не является внутренней командой | Python без галочки PATH | переустановить, поставить «Add python.exe to PATH» |
| `Не найден токен` | нет `.tg_token` / файл пустой | проверить имя (точка впереди) и содержимое |
| `Не найден ключ DeepSeek` | нет `.deepseek_key` или переменной | добавить файл или переменную |
| `Бот уже запущен (замок занят)` | работает второй экземпляр | закрыть лишнее окно, удалить `tools/.tg_bot.pid` |
| В журнале `Конфликт 409` | бот запущен на двух машинах с одним токеном | оставить один экземпляр |
| Бот молчит | ПК спит, нет интернета, задача не запущена | проверить журнал, «Электропитание», Планировщик |
| Ответ «Доступ закрыт» | `chat_id` нет в списке | вписать в `tg_config.json`, перезапустить |
| «Не удалось надёжно распознать» | фото смазано или обрезано | переснять ровнее, ближе, без блика |
| Модель не успела ответить | редкая ситуация с лимитом токенов | повторить отправку фото |

Журналы: `C:\PalladiumAutoBot\logs\tg_bot.log` (бот), `scan_cars.log` (пакетная обработка).
